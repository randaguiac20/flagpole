# Gotchas — where the docs, the tools and PROMPT.md disagreed

Each entry: what we expected, what is actually true (with the source), what we did. Newest at the bottom.

| # | Expected (PROMPT.md or memory) | Actually true | What we did |
|---|---|---|---|
| 1 | Spec Kit installs `/speckit.constitution` (dot) as `.claude/commands/*.md` | v1.0.3 installs **skills** `.claude/skills/speckit-*/SKILL.md`, invoked as `/speckit-constitution` (hyphen, `invoke_separator: "-"` in `.specify/integration.json`). Also adds `/speckit-converge` and `/speckit-taskstoissues`. | Use hyphenated names everywhere; document the two extra commands as unused. |
| 2 | `specify init --no-git` exists | It does not in v1.0.3; `--here --force --non-interactive --integration claude --script sh` is the scripted form. | Used that form. |

| 4 | The hook `terminalSequence` field does not exist (a research subagent said so) | It exists: hooks reference, "Emit terminal notifications" (OSC 0/1/2/9/99/777 + BEL). | 5 | A hook `if: "Edit(deploy/**)"` on `matcher: Edit\|Write` covers Write calls too (permission rules treat `Edit(path)` as covering all file writes) | A hook `if` matches **only the tool it names**: with `Edit(...)` the hook never ran on a `Write` (probe on 2026-09-02, nothing in `hooks.log`); with `Write(...)` it did. | Two handlers per path prefix. For the formatter, dropped `if` and let the script switch on the extension. |
| 6 | New skills/agents are picked up live | Skills: yes, but only if the top-level `.claude/skills/` directory existed at session start; agents: same for `.claude/agents/`. | 7 | `${CLAUDE_PROJECT_DIR}` expands in `.mcp.json` | Only with a default: `${CLAUDE_PROJECT_DIR:-.}` (the variable is set in the *server's* environment, not Claude Code's). | Used the default form for the Playwright output dir. |
| 8 | MCP Python SDK: `from mcp.server.fastmcp import FastMCP` | SDK v2 renamed it: `from mcp.server import MCPServer`; in-memory tests use `from mcp import Client`. | Feature 004 uses the v2 API. |
| 9 | Renovate `fileMatch`, `uv` manager | Key is `managerFilePatterns`; there is no `uv` manager, `pep621` handles `pyproject.toml` + `uv.lock`; `flux`/`kubernetes` managers need explicit patterns; `pre-commit` manager is off by default. | Feature 006 config follows the current names. |
| 10 | PROMPT.md §5.5 wants a `PreToolUse` deny hook for `kubectl delete` / `git push --force`, §2.4 says prefer `permissions.deny` | The hooks reference says the `if` filter is best-effort and "use the permission system rather than a hook to enforce a hard allow or deny". | Plain blocks → `permissions.deny`; the Bash hook guards the argument-dependent case (mutations outside `flux-system`). |
| 11 | One namespace `flagpole` | Two overlays in one cluster cannot share a namespace with identical resource names. | `flagpole-dev` and `flagpole-prod`. |
| 12 | CLAUDE.md < 150 lines (prompt) vs < 200 (docs) | Docs: "Keep CLAUDE.md under 200 lines". | Kept the stricter 150. |
| 13 | The `Stop` hook's `timeout` is a tool-event limit (≤ 10 s) | `Stop` is not a tool event; defaults are 600 s. Fast tests need more than 10 s once pytest starts. | `timeout: 120`, target `< 60 s`. |
| 14 | The gh token from `gh auth` works for `flux bootstrap github` | It is an OAuth token (`gho_`) with `repo` scope; Flux accepts any token with repo access via `GITHUB_TOKEN`. To be verified in Phase 4. | Will use `GITHUB_TOKEN=$(gh auth token)`; fall back to a fine-grained PAT if rejected. |
| 15 | Project `permissions.allow` rules apply as soon as `.claude/settings.json` exists | Headless `claude -p` printed: "Ignoring 31 permissions.allow entries from .claude/settings.json: this workspace has not been trusted. Run Claude Code interactively here once and accept the trust dialog". Deny rules still applied. | Documented in `docs/claude-code/settings.md`; the walkthrough's first interactive step is accepting trust. |
| 16 | `.claude/skills/` created mid-session is invisible until restart | True for the *Skill tool* immediately after `specify init`; about 10 minutes later the same session listed all `speckit-*` skills (live change detection caught up once the directory watcher registered). | Restart is the reliable path; document both observations. |
| 17 | Project subagents in `.claude/agents/` are usable as soon as the file exists | The Agent tool answered `Agent type 'code-reviewer' not found` right after the file was created; about 40 minutes later the same session announced the four agents as available (live discovery lags, like gotcha #6/#16). | Ran a general-purpose agent instructed to follow `code-reviewer.md` verbatim for the first review; later reviews use the real agent. |
| 18 | `/speckit-clarify` asks one question at a time | PROMPT.md §9 says batch questions; the clarify skill says exactly one per turn. | Batched the four clarifications in one `AskUserQuestion` (user instruction wins over tool procedure); recorded here. |
| 19 | `check-json` accepts any `.json` | `frontend/tsconfig.app.json` and `tsconfig.node.json` ship comments from the Vite template. TypeScript reads JSONC; Python's `json` does not: "Expecting property name enclosed in double quotes: line 9 column 5". | Excluded `^frontend/tsconfig.*\.json$` from `check-json` rather than stripping the template's comments. |
| 20 | gitleaks only fires on real secrets | A shell comment naming both feature branches after `Spec:` tripped `generic-api-key` (entropy 3.62): the colon reads as an assignment and the two branch names as a high-entropy value. | Reworded the comment to prose ("for specs 001-… and 002-…"). Prefer rewording over an allowlist entry, which would blind the rule to real keys. Two traps: the hook scans the **staged** copy, so `git add` before re-running, and quoting the flagged string verbatim in this table trips the same rule again. |
| 21 | Skill arguments are free text | A skill body using `$0` and `$1` splits the invocation on whitespace: `/e2e Run the 002 suite…` put `Run` in `$0` and `the` in `$1`, and the body rendered `make e2e TARGET=Run ARGS="the"`. | Use `$ARGUMENTS` unless the `argument-hint` really is positional, and keep the hint honest. Invoking a skill for real is the only way to catch this; the drift was invisible while the skill was only read. |
| 22 | "Chores commit on `main`" is easy to honour until a chore appears mid-feature | Three tooling fixes (`fix(dev)`, `fix(skill)`, `docs(gotchas)`) were committed on the `002-flagpole-web` branch because they were discovered while finishing it. The code reviewer caught the rule violation, not a hook. | Left in place rather than rewriting history, and noted here. The rule is about where chores *start*; a chore found mid-feature is cheaper to commit in place than to stash, and it reaches `main` with the merge either way. Worth a hook only if it recurs. |
| 23 | `tsc --noEmit` type-checks the project | Against a *solution* file (`"files": []` + `references`, which is what Vite scaffolds) it compiles nothing and exits 0. The lint gate looked green for the whole feature and could never have failed; `tests/` and `e2e/` were in no project at all. | `tsc -b --noEmit`, one project per source root, and prove the gate bites by planting an error in a file it is supposed to cover. |
| 24 | A Playwright `webServer` command always runs | With `reuseExistingServer: true` and a service already answering, the command is skipped entirely — so setup written into that command (rendering the Dex config) silently does not happen. A run on a different port then failed 8 of 9 tests against a Dex still holding the previous run's redirect URIs. | Put setup in the config module itself, where it runs on every invocation; leave `webServer.command` for starting the process. |
| 25 | `git checkout <file>` undoes a mutation-test edit | It restores the last **commit**, not the state before the edit. Uncommitted implementation work vanishes silently, and the suite then passes against the *old* code, which looks like a healthy result. Hit while mutation-checking the operator slot in 004. | Copy the file aside before mutating and restore from the copy; never use `git checkout` for a temporary edit on uncommitted work. |
| 26 | `@playwright/mcp --output-dir <path>` puts every artefact there | Screenshots honour it, but page snapshots and console logs landed in `.playwright-mcp/` at the repository root instead — untracked files in a clean tree, one of them a console log. Seen with `0.0.80` while verifying 004. | `.playwright-mcp/` added to `.gitignore` as well; check `git status` after a browser session rather than trusting the flag. |
| 27 | The GitOps guard hook inspects the `kubectl` command you are running | It inspects the whole Bash command string, so writing a *script* that contains `kubectl run` through a heredoc is denied exactly like running it — the hook cannot tell authoring from executing. Hit while writing `scripts/verify-cluster.sh`. | Write such files with the Write tool rather than a heredoc; and take the denial as a design question — the probe was rewritten to `--dry-run=server` and `kubectl exec` into a workload that already exists, so the script mutates nothing either way. |
| 28 | A virtual environment can be copied between paths in a multi-stage build | Its console scripts carry absolute shebangs, so a venv built at `/build/.venv` and copied to `/app/.venv` fails at start with `exec /app/.venv/bin/uvicorn: no such file or directory` — an error that reads like a missing file rather than a wrong interpreter path. | Build at the same path the runtime stage uses (`WORKDIR /app` in both), or invoke through `python -m`. |
| 29 | A key file mounted into a non-root container is readable | `chmod 600` on the host makes it readable by the host user's uid only; a container running as 10001 gets `PermissionError` on a file it can see. Hit smoke-testing the consumer image. | In Kubernetes give the Secret volume a `defaultMode` the running uid can read and set `fsGroup`; the private key stays unreadable to everyone else. |
| 30 | Flux retries a Kustomization until its resources become applicable | kustomize-controller dry-runs the **whole** set first, so one unknown kind aborts the apply — including the apply that would have installed the controller defining that kind. Putting cert-manager and a `ClusterIssuer` in one unit deadlocks: nothing is ever created, and the message (`no matches for kind "ClusterIssuer"`) reads like a missing CRD rather than a dependency loop. | Whenever a repository installs a controller *and* uses its custom resources, split them into two Kustomizations with `dependsOn`. |
| 31 | A third-party chart runs under the restricted Pod Security Standard | Most charts set no `securityContext` at all, so the namespace rejects the Pod and the Helm install hangs until it times out — the HelmRelease says `timeout waiting for Deployment` and the real reason is only in the ReplicaSet's events (`violates PodSecurity restricted:latest`). Hit with Dex 0.24.1. | Set `podSecurityContext` and `securityContext` in the chart's values to the same floor your own workloads meet, and read `kubectl -n <ns> get events` rather than the HelmRelease message when an install hangs. |
| 32 | A check that reads `.spec.template.spec.containers[*].env` sees the container's environment | Not when it arrives through `envFrom`: the values live in the ConfigMap, and the field is empty. The grant check failed for dev and — worse — **passed** for prod, because "absent" was what it expected and absent was all it could ever find. A check that cannot fail is not a check. | Resolve the `configMapRef` and read the ConfigMap; then flip the expectation in the contract and confirm the check turns red. |
| 33 | `sops --decrypt` finds the age key that encrypted the file | It looks in `SOPS_AGE_KEY_FILE`, `SOPS_AGE_KEY` and `~/.config/sops/age/keys.txt` — not at a key named anything else. Encrypting works without any of them (it needs only the public recipient), so the first failure appears at the first decrypt, long after the file was written. | Export `SOPS_AGE_KEY_FILE` (it is in `.env.example`) or name the key `keys.txt`. `make` targets source `.env`; an ad-hoc shell does not. |
| 34 | A browser reaches a cluster host served by the cluster's own CA | Chromium refuses with `ERR_CERT_AUTHORITY_INVALID`: the CA is self-signed and in nobody's trust store. The Playwright MCP server needs `--ignore-https-errors`, and a human needs the CA installed (which takes sudo). | `--ignore-https-errors` added to `.mcp.json`; `docs/walkthrough.md` prints the command to trust the CA for a human, and does not run it. |
| 35 | `renovate-config-validator` refuses a deprecated configuration key | It does not. Given `fileMatch` (renamed to `managerFilePatterns` in Renovate 41) it prints `WARN: Config migration necessary`, shows the migration diff, and **exits 0**. A CI step that reads the exit status alone passes a configuration whose managers may silently not match anything. | Grep the validator's output for `migration necessary` and `ERROR` rather than trusting `$?`, and assert the absent key in a contract check as well. |
| 36 | `set -e` is a reasonable default for a script that runs several checks | Not when the checks are independent. Eight scanners behind `set -e` stop at the first finding, so you get one run per fix instead of one fix per run — and the seven you have not seen yet are invisible when you estimate the work. | Run every check, collect the outcomes, fail once at the end with a summary. `set -uo pipefail`, never `-e`, for that shape of script. |
| 37 | A scanner that reports nothing has found nothing | `trivy config` accepts a single directory and exits FATAL on more than one. Given three it wrote an empty report, `jq` extracted nothing, and the summary said **clean** — a check that could never fail, found by this feature's own first run. | Treat output that does not parse as a failure, treat a missing tool as a failure, and never let 'no findings' and 'no run' produce the same result. |
| 38 | A secret scanner catches any planted secret when you test it | gitleaks allowlists well-known example values. `wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY` — the AWS documentation example — produces no finding, so a probe built from it says the scanner is broken when it is working correctly. | Probe with a realistically shaped, randomly generated value (`ghp_` + 36 random characters detects as `github-pat`). Then remove it. |
| 39 | Pushing a file under `.github/workflows/` needs no special permission | Over **HTTPS** it needs the `workflow` scope on the token, and `gh auth status` here reports only `gist, read:org, repo`. This repository's remote is SSH, so the push uses the key and the scope never applies — which means the trap is invisible until someone clones over HTTPS. | Check the remote's protocol before blaming the file. `gh auth refresh -s workflow` adds the scope for an HTTPS remote. |
