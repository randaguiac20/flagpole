# Decision: eight scanners, one command, one findings document

- **Problem / trigger**: scanners produce findings faster than anyone fixes them, and an unread list is the same as no scanner. The question is not which tools to run — it is what happens to what they say.
- **Alternative rejected**: per-scanner suppression files (eight formats, eight places to look, and the reason lives next to the *rule* instead of next to the *risk*); failing on everything including `LOW` (the first transitive `LOW` in a dev dependency stops the build and teaches that the fix is to disable the scanner); listing the scanners in the workflow rather than in a script (two lists, which is how the local run and the automated run stop agreeing).
- **Limits**: `scripts/scan.sh` covers language dependencies (pip-audit, npm audit, osv-scanner), images and manifests (trivy), Dockerfiles (hadolint), secrets (gitleaks) and source (bandit, semgrep). It does **not** `set -e` — eight scanners behind `set -e` means the first finding hides the other seven. A tool that is not installed is a failure, not a skip. A finding at or above its threshold fails the run until it has a row in `docs/security-findings.md` with a decision, a reason and a date, which is what makes that document the only way past a scanner. Versions come from `.mise.toml`, so the local run and CI use the same ones.
- **Not done**: no CodeQL (semgrep and bandit already cover this much code; a second SAST tool adds overlap, not coverage); no nightly schedule (the scanners run on every change, and a nightly run would mostly re-report yesterday's triage); no coverage threshold (a percentage is not the guarantee the constitution asks for — removing a behaviour and watching exactly one test fail is). One input is **not** pinned and it is worth naming: semgrep's rule *contents* come from the registry (`p/python`, `p/typescript`, `p/bash`). The signal to vendor them is the first time a rule change, rather than a code change, turns the build red.
- **Verification** (2026-09-02): `make scan` runs all eight and exits 0 with every finding accounted for. Both guarantees were proved by breaking them: a planted `ghp_…` token gives `github-pat` and exit 1; hiding `gitleaks` from `PATH` gives `NOT INSTALLED` and exit 1 rather than a clean report. The first real run also caught a bug in itself — `trivy config` given three directories exits FATAL, and the empty report was being reported as clean.
