# Decision: Renovate, through the Mend-hosted app

- **Problem / trigger**: feature 005 pinned everything — image digests, chart versions, action SHAs, lockfiles, pre-commit revisions, tool versions. Pinning without a mechanism to update is how a repository becomes a museum of the day it was written.
- **Alternative rejected**: **Dependabot**, and this one deserves an honest hearing. It is simpler, needs no app installation, and if this repository had only npm and Actions it would be the right answer. It has no `pre-commit`, `helm-values`, `flux` or `mise` manager, and it cannot group across ecosystems — which for a repository that deliberately pins seven different kinds of thing would leave four of them unwatched. Also rejected: self-hosted Renovate on a schedule (a token with write access, running unattended, for a demo).
- **Limits**: nine managers, two of which (`pre-commit`, `kubernetes`) are off by default and enabled explicitly — a manager that is off silently is a set of pins nobody is watching. `pinDigests: true` so an update cannot turn a digest back into a tag. Non-major updates grouped per ecosystem, `prConcurrentLimit: 3` and `prHourlyLimit: 2`. A weekly `schedule` was configured first and removed on the day the app was installed: it delayed every proposal by up to a week and added nothing the concurrency limit did not already do. The limit bounds how much there is to review; a window only bounds when you learn about it. Majors arrive alone and unscheduled: a major is a decision, not a bump. `automerge: false` everywhere. The images this repository publishes are excluded — they move because `VERSION` moved, not because an updater proposed a bump to itself.
- **Not done**: no Flux image automation (it would write the same tags Renovate already writes, and two mechanisms updating one field is a conflict waiting to happen); no `renovate.json` in `.github/` (root, where a reader looks); nothing in this repository holds a token for Renovate — the app is installed on the repository by its owner.
- **Verification** (2026-09-02): `renovate-config-validator` reports `Config validated successfully`. Worth knowing, and contrary to the note made during discovery: the validator does **not** refuse the deprecated `fileMatch` key. It prints `WARN: Config migration necessary`, shows the diff, and exits 0. So the CI step reads its output rather than its exit status, and `scripts/check-ci-contract.sh` asserts the key is absent.
