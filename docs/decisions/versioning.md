# Decision: a VERSION file, changed by a person

- **Problem / trigger**: images published from the default branch need a tag that means something in `deploy/`, and the updater needs a *newer* tag before it can propose anything. Something has to decide what that number is.
- **Alternative rejected**: `semantic-release` / `release-please` — a tool, a changelog, a tagging step and a bot commit, to decide a number a person can type; the version also becomes a side effect of how a commit message was phrased. Git tags as the source (the version then lives outside the tree Renovate reads). A `latest` tag (exactly the moving reference feature 005 spent its effort removing).
- **Limits**: one line, `MAJOR.MINOR.PATCH`, at the repository root. `scripts/build.sh` and `scripts/deploy.sh` read it; `release.yml` reads it and publishes each image twice — `:<VERSION>` and `:sha-<short commit>`, both pointing at one digest. Nothing writes it, and the contract check asserts that no workflow or script does (FR-005a). Publishing a version that already exists is refused, naming the file to bump, rather than silently moving a tag someone has pulled.
- **Not done**: no changelog generation, no git tag, no release notes. When this repository has consumers who need to know what changed, that is the signal — until then a generated changelog is a file nobody reads describing changes nobody depends on.
- **Verification** (2026-09-02): `VERSION` holds `0.1.0`; `scripts/check-ci-contract.sh` passes both the shape assertion and "no workflow or script writes VERSION". The republish guard is exercised by the first push to `main`.
