# Decision: GitHub Actions, two workflows

- **Problem / trigger**: a check that only runs when someone remembers is not a check. Every change needs the lint, the tests of all four codebases, the hook tests and the scanners to run before anyone reviews it, on a machine that is not the author's.
- **Alternative rejected**: a self-hosted runner (a machine to keep patched, for a repository whose whole point is that everything is reproducible from an empty directory); pre-commit alone (`--no-verify` skips it, so it is a convenience, not a gate); one workflow with `if:` on every job (FR-004 and FR-005 — "documentation must not build", "only the default branch publishes" — become six conditions nobody can read together).
- **Limits**: two files. `ci.yml` has `permissions: {contents: read}` and no path filter, so a change to a rule, a hook or a spec still sees the lint and the hook tests run. `release.yml` carries the only write scope in the repository (`packages: write`) on the only job that needs it. Neither uses `pull_request_target`, and the contract check refuses one that does. Every `uses:` names a commit SHA with the tag in a comment.
- **Not done**: no CodeQL beside semgrep and bandit (two SAST tools on this much code produce overlapping findings and a longer triage list, teaching that scanning is a volume exercise); no SBOM, provenance or signing (right when someone else deploys these images — nothing consumes them yet); no version matrix (the repository pins one Python and one Node, and the cluster runs exactly those); no deploy job (Flux owns the cluster — publishing an image is where continuous integration stops).
- **Verification** (2026-09-02): `actionlint` clean on both files; `scripts/check-ci-contract.sh` reports 105 passed, 0 failed. Both refusals were proved rather than assumed — changing `pull_request` to `pull_request_target` gives 103 passed, 2 failed, and adding a step that writes to the cluster gives 104 passed, 1 failed.
