# Research: 001-flagpole-api

All unknowns from the Technical Context resolved. Sources are official docs or PyPI metadata fetched on 2026-09-02.

## R1 — Token validation without a bypass, testable offline

- **Decision**: `auth.py` defines a `KeyResolver` protocol (`resolve(token: str) -> key`). Production binds `JwksKeyResolver` around `jwt.PyJWKClient(settings.oidc_jwks_url)` (cached keys, `get_signing_key_from_jwt`). Tests override the FastAPI dependency `get_key_resolver` with `StaticKeyResolver(public_key)` and sign tokens with a per-session RSA key (`cryptography`, via `pyjwt[crypto]`). `jwt.decode(..., algorithms=["RS256"], audience=settings.oidc_audience, issuer=settings.oidc_issuer, options={"require": ["exp", "iss", "aud", "sub"]})` always runs.
- **Rationale**: FR-011 forbids a validation switch; overriding *where keys come from* keeps every check active. No HTTP server in tests, no network (constitution III).
- **Alternatives considered**: env flag `AUTH_DISABLED` (bypass in prod code; rejected by the user in clarification); real Dex in docker compose for tests (Docker dependency for unit tests); `python-jose` (last release 2025-05, low activity; PyJWT is maintained).

## R2 — ORM and migrations

- **Decision**: SQLAlchemy 2.0 typed declarative mappings (`Mapped[...]`, `mapped_column`), synchronous engine (FastAPI runs sync endpoints in a threadpool; the app is tiny). Alembic with one hand-checked autogenerated revision `0001_initial`. `make dev` and the container entrypoint run `alembic upgrade head`; the app never calls `create_all` (rule: python-services).
- **Rationale**: FR-016 versioned schema; identical behavior on SQLite and PostgreSQL (`postgresql+psycopg`). Sync avoids `aiosqlite`/`asyncpg` split drivers.
- **Alternatives**: async SQLAlchemy (two drivers, more moving parts for no load); SQLModel (extra layer); raw SQL (no migrations story).

## R3 — Deterministic bucket

- **Decision**: `bucket = int.from_bytes(hashlib.sha256(f"{flag_key}:{user_id}".encode()).digest(), "big") % 100`; `enabled = bucket < rollout_percent`. Documented in the spec (FR-009) and the OpenAPI description so consumers/UI can reproduce it.
- **Rationale**: stable across languages and restarts; uniform enough for SC-002 (45–55% at rollout 50 over 10k users; verified in a test with fixed IDs `u-0…u-9999`).
- **Alternatives**: MurmurHash (extra dependency); `hash()` (salted per process, non-deterministic).

## R4 — Metrics

- **Decision**: `prometheus-fastapi-instrumentator` 8.1 (`Instrumentator().instrument(app).expose(app, endpoint="/metrics", include_in_schema=False)`) + a `Counter("flagpole_evaluations_total", ..., ["env", "reason"])` incremented in the evaluate router.
- **Rationale**: FR-013 standard scrape format with request count/latency; the evaluation counter is the one domain metric the demo dashboards need.
- **Alternatives**: hand-rolled middleware with `prometheus_client` (more code); OpenTelemetry (out of scope).

## R5 — Audit pagination and filter

- **Decision**: `GET /audit?limit=50&before=<id>&flag_key=<key>`; `id` is an autoincrement integer used as the cursor; results ordered by `id DESC`; `limit` 1–200. Response `{items: [...], next_before: <id|null>}`.
- **Rationale**: FR-007 cursor on the last entry seen; integer ids are monotonic in both SQLite and PostgreSQL for a single writer; the filter was added in clarification.
- **Alternatives**: offset pagination (skips/duplicates under inserts); timestamp cursors (ties).

## R6 — Error shape and validation

- **Decision**: FastAPI defaults: 422 for schema validation, but the spec says "rejected as invalid"; we register a handler that maps `RequestValidationError` to **400** with `detail` = first error message, so consumers see one code for "invalid input" (api-conventions). 401 `detail: "missing or invalid token"`, 403 `"operator role required"`, 404 `"unknown flag"` (only on `PUT`; `/evaluate` never 404s), 409 `"flag already exists"`.
- **Rationale**: FR-017 stable `detail`; one status per failure class.
- **Alternatives**: keep 422 (FastAPI default) — rejected for consistency with the spec wording and the UI's error handling.
