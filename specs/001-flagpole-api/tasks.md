# Tasks: Flagpole API (flags, environments, evaluation)

**Input**: Design documents from `/specs/001-flagpole-api/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/openapi.yaml, quickstart.md

**Tests**: REQUIRED (constitution III: test-first; SC-007 "every FR has a test that fails when the behavior is removed"). Each story phase writes its tests first, runs them red, then implements.

**Organization**: grouped by user story so each is an independently testable increment.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task)
- **[Story]**: US1–US4 from spec.md
- Paths are repository-relative; the service lives under `backend/`

## Dependencies

- Phase 1 → Phase 2 → stories. US1 (Phase 3) is the MVP: it needs T005–T012 only.
- US2 needs US1's flags to exist for API tests (seeded in the test); `evaluation.py`/`metrics.py` are independent of US1 and marked [P].
- US3 needs US1 (audit rows come from flag writes). US4 is independent of all stories.
- Phase 7 tests need Phase 2 (auth) and US1 (seed); Phase 8 needs everything.

## Implementation strategy

MVP = Phases 1–3 (flags + audit with auth): demonstrable with the quickstart. Then US2 (the product), US3, US4, cross-cutting tests, polish, review. Each story phase ends with its test file green and a commit (`feat(api): …` with `Spec: 001-flagpole-api`).
